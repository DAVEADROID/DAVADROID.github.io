02 / featured project

Enterprise PKI Lab

A multi-tier certificate authority built from scratch, then attacked with a rogue CA to watch validation fail.

Chain valid Client follows the chain from the intranet certificate to ACME-LAB-ISSUING to ACME-LAB-ROOT, which it trusts.

Why I built it

The standard explanation of certificates and PKI did not fully click while I was studying for Security+, so I built one to see it work.

What I did

  • Designed and deployed a multi-tier PKI: a Root CA and an Enterprise Subordinate Issuing CA.
  • Configured certificate issuance for internal HTTPS on IIS.
  • Worked hands-on with certificate chains, trust, validation, and CRLs.
  • Ran a man-in-the-middle simulation with a rogue certificate authority to show how certificate validation fails.

Lab setup

domain: acme-lab.local, 5 VMs

  2. Enterprise Subordinate Issuing CAACME-LAB-ISSUING

04 / projects

Other projects

infrastructure, cost

This portfolio site

Built with HTML, CSS, and JavaScript. It started on AWS S3 with Route 53 for DNS. To cut costs I moved DNS to Cloudflare and hosting to GitHub Pages, and now manage it through GitHub.

Lessons learned

  • Cost: a static site does not need paid hosting. Moving off S3 and Route 53 cut the bill.
  • DNS: migrating a domain between providers means planning the record changes so the site stays reachable.
  • Deployment: with GitHub Pages, a push to the main branch is the deploy, and the history is the change log.
